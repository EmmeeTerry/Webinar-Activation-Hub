3. Choose ONE way to publish AND emailBoth options result in a SharePoint page and an email. They differ in where the email is sent from.
OPTION A: SharePoint News → Email from SharePoint

ONE workflow, TWO results: Create a SharePoint News post and use Send as email from SharePoint. No separate Outlook email. Uses native Text and Image web parts.

Create a new Made for email post (or an email-compatible copy of the template). Paste text into a Text web part, upload covers as Image web parts, preview the page and Send as email, then publish and send after approval. No iframe.

OPTION B: Branded SharePoint page + separate Outlook email

TWO REQUIRED ACTIONS: First publish the branded SharePoint webpage. THEN send the matching Outlook email. Do BOTH to complete this option. The iframe does not send an email.

STEP 1 OF 2: PUBLISH ON SHAREPOINT

Open SharePoint page template ↗

Open the SharePoint page template, create a new copy (do not overwrite the template), add an Embed web part and paste the iframe. Review, then publish. The iframe is web-only; SharePoint's full-body email cannot include it.

STEP 2 OF 2: SEND VIA OUTLOOK (ALSO REQUIRED)

Open the .eml in Classic Outlook, check images and links, verify it is editable, add recipients, test and send. This email is separate from the SharePoint page. Some Outlook versions open .eml read-only.

Other email methods if .eml does not work

Copy/paste has not reliably preserved cover images in Classic Outlook. These alternatives are provided only as fallback.

For Classic Outlook: If the embedded-image .eml opens read-only, try the Word-compatible file. Open it in Word, verify images, select the email content, then copy into a new Outlook message. This may preserve more formatting than copying directly from a browser. Neither method is guaranteed; test before sending.
